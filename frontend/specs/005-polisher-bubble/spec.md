# Feature Specification: 拓展润色气泡

**Feature Branch**: `005-polisher-bubble`

**Created**: 2026-10-27

**Status**: Draft

**Input**: 用户描述：当用户输入的句子语法正确但表达可更地道时（润色分支），对话反馈以润色气泡展示：原句行 + 功能行（文A｜拓展润色｜AI 发音）+ 润色建议（You can also say: "..."）+ 操作栏（循环跟读｜复制｜收藏｜AI 发音）+ 气泡下方评分条。流程沿用 003/004 的 spec-kit 全流程。

**原型图**: `frontend/docs/mockups/子功能-对话演示气泡-拓展润色场景.jpg`（原则 IV 视觉事实来源，每一步对照）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看到润色建议 (Priority: P1)

用户说出语法正确但表达平淡的句子（如 "Recently, I am learning English."），本轮反馈渲染为润色气泡：原句行 + 功能行 + 润色建议区（默认展开）。点「拓展润色」可收起/展开建议区。

**Why this priority**: 润色气泡的存在本身是本功能核心价值——用户每轮都获得可见、可学的反馈。

**Independent Test**: 输入一句语法正确但有更地道说法的英文，观察反馈消息是否渲染为带润色建议的气泡。

**Acceptance Scenarios**:

1. **Given** 用户输入语法正确且有更地道表达，**When** 本轮反馈出现，**Then** 消息渲染为润色气泡（原句行 + 功能行 + 润色建议行），而非普通 AI 气泡
2. **Given** 润色气泡处于展开态，**When** 点击「拓展润色」，**Then** 建议区收起、箭头翻转向下；再点恢复展开
3. **Given** 润色建议区展开，**When** 渲染完成，**Then** 建议行以 `You can also say: "<润色句>"` 格式展示，润色句为纯英文文本
4. **Given** 同一轮对话反馈，**When** 渲染，**Then** 纠错气泡（003）与润色气泡互斥出现，不同时渲染

---

### User Story 2 - 润色气泡的操作能力 (Priority: P2)

润色气泡内的既有操作能力全部可用：功能行「文A」翻译（作用于原句，004 全套行为）、功能行「AI 发音」（播原句）；操作栏「循环跟读」「复制」「AI 发音」（作用于润色句）、「收藏」（占位）。

**Why this priority**: 操作能力让建议可练、可存，但依赖 US1 的气泡存在。

**Independent Test**: 在润色气泡上逐一点击五个操作入口，确认各自行为与作用对象正确。

**Acceptance Scenarios**:

1. **Given** 润色气泡，**When** 点击「文A」，**Then** 译文区出现在功能行正下方（004 同布局），内容为原句的中文译文，含加载/失败重试/缓存零等待全套行为
2. **Given** 润色气泡，**When** 点击功能行「AI 发音」，**Then** 播放原句；点击操作栏「AI 发音」，**Then** 播放润色句；两处共享全局音频互斥
3. **Given** 润色气泡，**When** 点击「复制」，**Then** 润色句写入剪贴板，按钮显示对勾反馈约 1.5 秒
4. **Given** 润色气泡，**When** 点击「循环跟读」，**Then** 打开底部跟读面板，跟读内容为润色句
5. **Given** 润色气泡，**When** 点击「收藏」，**Then** 显示「功能开发中」轻提示，无副作用

---

### User Story 3 - 降级与零回归 (Priority: P3)

润色服务失败或无实际润色产出时，反馈消息退回普通渲染，不出现空壳气泡；普通对话、003 纠错气泡、004 翻译行为零回归。

**Why this priority**: 保证功能异常时体验不劣化、既有能力不回退。

**Independent Test**: 停用润色服务后输入语法正确的句子，确认反馈为普通消息且无报错；再输入语法错误句子确认纠错气泡不受影响。

**Acceptance Scenarios**:

1. **Given** 润色服务不可用（后端保留原文降级），**When** 反馈出现，**Then** 渲染为普通消息（含「当前语句没有错误」类文案），不渲染润色气泡
2. **Given** 润色结果与原句相同（无实际建议），**When** 反馈出现，**Then** 同样渲染为普通消息
3. **Given** 用户输入语法有误的句子，**When** 反馈出现，**Then** 仍为 003 纠错气泡，功能与 003 验收时一致
4. **Given** 普通 AI 对话消息（如话题追问），**When** 渲染，**Then** 不出现润色气泡或润色区

---

### Edge Cases

- 润色句与原句相同或润色服务降级时，反馈消息如何处理？→ 不套润色气泡，按普通消息渲染（US3）
- 原句为空时点「文A」？→ 沿用 004 行为：显示「原句为空，无法翻译」不可用终态
- 页面刷新后历史润色气泡？→ 数据关联失效时降级为普通渲染，不报错（与 003 同策略）；会话内通过缓存保持历史气泡持续展示
- 跟读面板播放时点击 AI 发音？→ 全局音频互斥，前一路停止（沿用 003 既有互斥机制）
- 翻译请求进行中快速重复点击「文A」？→ 沿用 004 防重与四态状态机，不重复实现

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在润色分支（语法正确且有润色建议）的反馈轮次渲染润色气泡，默认展开
- **FR-002**: 润色气泡必须展示原句行（完整原句，普通样式渲染）
- **FR-003**: 功能行必须包含三个入口：「文A」翻译开关、「拓展润色」展开/收起开关（箭头随状态翻转）、「AI 发音」（播放原句）
- **FR-004**: 展开区必须以 `You can also say: "<润色句>"` 格式展示润色建议，位于功能行之下、操作栏之上，以虚线分隔
- **FR-005**: 操作栏必须包含「循环跟读」「复制」「收藏」「AI 发音」四项，前两项与 AI 发音的作用对象为润色句
- **FR-006**: 「文A」翻译必须复用 004 翻译的全部既有行为（四态状态机、加载防重、会话缓存零等待、空原句不可用终态），翻译对象为原句
- **FR-007**: 气泡下方评分条必须展示「语法正确 ✓（太棒了）」与「发音 X（发音分析入口）」（有评测数据时）；「地道」项不渲染（延续 003 决议：后端无数据源）
- **FR-008**: 系统必须能可靠识别润色分支的反馈消息并获取其结构化润色数据（原句、润色句、解释、润色状态）；当前后端反馈消息未携带结构化润色数据，需做最小后端适配（原则 II，具体方案在 plan.md 留档）
- **FR-009**: 无润色产出（服务降级、润色句与原句相同）时，系统不得渲染润色气泡，反馈按普通消息展示
- **FR-010**: 普通对话消息、003 纠错气泡、004 翻译行为必须零回归
- **FR-011**: 润色气泡的音频行为必须纳入既有全局音频互斥（同一时刻仅一路音频播放）

### Key Entities *(include if feature involves data)*

- **PolisherResult（后端润色产出）**: 本轮润色分支的结果数据，包含原句、润色后句子、中文解释、润色状态（成功/降级/跳过）、语音合成状态；随反馈消息提供给前端
- **PolisherMessageData（界面消费结构）**: 原句（渲染原句行与翻译输入）、润色句（建议行、复制、跟读、发音的输入）、中文解释（本期不展示，字段保留）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 连续输入 10 句「语法正确但表达可提升」的英文，润色气泡渲染成功率 100%（10/10）
- **SC-002**: 「拓展润色」展开/收起为即时本地交互，无可感知延迟（< 100ms）
- **SC-003**: 操作栏与功能行共 5 个操作入口全部可用，发音/跟读的实际播报内容为润色句（抽查 3 句确认）
- **SC-004**: 零回归验证：003 纠错气泡验收清单（quickstart §5 全项）与 004 翻译验收（quickstart §1~§5）复测全部通过

## Assumptions

- 「You can also say: 」前缀为界面固定文案，非 AI 产出
- 后端已产出的中文解释字段本期不在气泡内展示（原型图未包含该内容；后续 feature 可增量加入）
- 原句不做片段级高亮（原型图中 "I am" 的橙色高亮）：后端润色契约无错误片段数据，与 003「地道项不渲染」同类处理（无数据源不造假数据）
- 润色气泡默认展开（原型图为展开态 ∧ 003 纠错气泡默认展开先例）
- 气泡自上而下布局：① 原句行；② 功能行（文A｜✨拓展润色 ∧/∨｜AI 发音）；③ 虚线分隔；④ 润色建议行；⑤ 操作栏（循环跟读｜复制｜收藏｜AI 发音）；气泡下方独立评分条
- 润色数据的消息级关联沿用 003 既有双路径机制（消息元数据直读 + 同源字段关联 + 按消息 id 会话级缓存）
- 后端适配限于「随现有反馈消息附带结构化润色数据」，不修改润色子图内部逻辑、节点拓扑与模型调用
- 本 feature 无新增截图入库，布局以既有原型图 + 本 spec 文字描述为准
