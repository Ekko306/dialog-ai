# Feature Specification: 子功能-语音工具-选场景弹出弹窗

**Feature Branch**: `002-scene-select-popup`

**Created**: 2026-10-23

**Status**: Draft

**Input**: User description: "搭建子功能-语音工具-选场景弹出弹窗：从下方弹出弹窗，顶部标题'选择场景或角色'，下面一栏是滑动的各个目录，中间部分为各个话题，点击进入对应场景，底部有一个按钮；页面功能基于第一个 Tab 的主页上面添加；原有兼容功能（创建新对话、回复 HITL、看到后端反应和自己的对话内容）原样放进 Tab 里；前 4 步完成后再根据原型图对 UI 进行优化（圆角、主题色、输入框样式）；最后可适当修改后端代码匹配页面内容和功能"

**布局基准**: 所有其他子功能的布局以 Tab1 主窗口（自由对话主页）为基准搭建；本功能是在主窗口之上叠加的底部弹窗，不改变主窗口结构。

## Clarifications

### Session 2026-10-23

- Q: 在弹窗中点选一个场景后，它何时对对话生效，与后端现有 HITL"切换下一个场景"指令（`_new_context_`）是什么关系？ → A: 立即生效于当前对话；HITL"切换下一个"指令保留，两者并存
- Q: 通过弹窗选择场景后，这个选择在"新建对话"时是否保留？ → A: 跨新对话保留，直到用户再次选择其他场景
- Q: 再次打开场景弹窗时，分类栏与卡片的初始状态应该是什么？ → A: 每次打开都回到默认状态（选中"热门"分类，无场景选中标记），与原型图一致
- Q: 五个分类下的初始场景话题清单（含图标、中英文名）从哪里来？ → A: 以原型图可见话题为初始集，其余分类内容由实现时合理拟定，用户可随时替换静态数据

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从主页打开场景弹窗并浏览分类与话题 (Priority: P1)

用户在 Tab1 主页（自由对话）点击"选场景"入口，弹窗从屏幕底部滑出；弹窗顶部为标题"选择场景或角色"与关闭按钮，标题下方是一行可横向滑动的分类胶囊（热门 / 今日话题 / 日常交流 / 旅游出行 / 职场），默认选中"热门"并以主题色高亮；弹窗中部以双列卡片网格展示当前分类下的场景话题，每张卡片含图标、中文话题名与英文名，内容可纵向滚动；点击关闭按钮或遮罩区域后弹窗收回，回到打开前的主页状态。

**Why this priority**: 弹窗是本功能的核心载体，浏览是用户选择场景的前置路径；没有它后续选择与自定义入口均无意义。

**Independent Test**: 仅实现本故事即可演示：从主页唤起弹窗、滑动分类、滚动话题卡片、关闭弹窗，全程不报错且主页对话功能不受影响。

**Acceptance Scenarios**:

1. **Given** 用户位于 Tab1 主页且未打开弹窗，**When** 点击"选场景"入口，**Then** 弹窗从底部滑出，标题显示"选择场景或角色"，右上角有关闭按钮，主页内容在弹窗背后仍可见
2. **Given** 弹窗已打开，**When** 左右滑动分类栏，**Then** 分类胶囊可横向滚动到被遮挡的分类，当前选中分类以主题色高亮
3. **Given** 弹窗已打开且"热门"分类被选中，**When** 查看中部区域，**Then** 以双列卡片网格展示该分类的场景话题，每张卡片含图标、中文名、英文名，内容超出时可纵向滚动
4. **Given** 弹窗已打开，**When** 点击其他分类胶囊，**Then** 中部话题卡片即时切换为该分类的内容，无需刷新页面
5. **Given** 弹窗已打开，**When** 点击关闭按钮，**Then** 弹窗收回，回到打开前的主页状态，正在进行的对话不中断

---

### User Story 2 - 点击话题卡片进入对应场景对话 (Priority: P2)

用户在弹窗中点击某个场景话题卡片（如"求职面试 / Job Interview"），弹窗关闭，所选场景与角色被应用到后续对话；用户随后发送消息，收到的教练回复与所选场景一致。原有的对话能力在此过程中保持原样：创建新对话、回复 HITL 中断、看到后端反应与自己的对话内容，行为与选场景之前完全一致。

**Why this priority**: "点击进入对应场景"是本功能的最终价值；但依赖 US1 的弹窗载体，故列于 P2。

**Independent Test**: 选定一个场景后发送一条消息，人工判读回复内容贴合所选场景；再用"新建对话"与一次 HITL 应答验证既有功能无回归。

**Acceptance Scenarios**:

1. **Given** 弹窗已打开，**When** 点击某张场景卡片，**Then** 弹窗关闭，该场景与对应角色立即生效，当前对话的下一条回复即按新场景生成
2. **Given** 已选择"求职面试"场景，**When** 用户发送一条英文消息，**Then** 教练回复的内容与角度贴合求职面试场景（人工判读）
3. **Given** 已选择任一场景，**When** 用户使用"新建对话"功能，**Then** 新对话正常创建且沿用最近选择的场景（跨新对话保留）
4. **Given** 对话过程中出现 HITL 中断（如是否生成语音、切换场景询问），**When** 用户在输入区应答，**Then** 应答被后端正常接收并继续流程，与既有行为一致
5. **Given** 已选择场景并继续对话，**When** 用户查看消息流，**Then** 自己发送的消息与后端回复均正常展示，与既有行为一致
6. **Given** 已通过弹窗选择某场景，**When** 用户使用 HITL"切换下一个场景"指令（`_new_context_`），**Then** 指令按既有轮换行为执行，不受弹窗选择影响（两者并存）

---

### User Story 3 - UI 视觉对齐原型图 (Priority: P2)

功能通路完成后，按原型图对相关 UI 进行视觉优化：弹窗顶部圆角、整体主题色（绿色系高亮）、分类胶囊选中态、话题卡片的圆角与阴影、主页底部输入框与按钮样式。实现效果与原型图逐项目视比对一致。

**Why this priority**: 用户明确要求在功能完成后再做 UI 优化；与原型图一致是验收的硬性标准（ Constitution 原则 IV），故列 P2 而非 P3。

**Independent Test**: 将实现界面与原型图并排目视比对，逐项核对弹窗结构、配色、圆角、卡片样式与输入框样式。

**Acceptance Scenarios**:

1. **Given** 功能通路已完成，**When** 打开弹窗并与原型图比对，**Then** 弹窗顶部圆角、白色底、标题栏布局与原型图一致
2. **Given** 弹窗已打开，**When** 查看分类栏与选中态，**Then** 选中分类以主题色（绿色系）胶囊高亮，未选中为浅色胶囊，与原型图一致
3. **Given** 弹窗已打开，**When** 查看话题卡片，**Then** 卡片为浅色圆角样式、含图标与中英文名排版，与原型图一致
4. **Given** 回到主页，**When** 查看底部输入框与按钮区，**Then** 输入框与按钮的圆角、配色样式与原型图风格一致

---

### User Story 4 - 底部"自定义场景/角色"入口 (Priority: P3)

弹窗底部固定展示"自定义场景/角色"按钮（浅绿色胶囊样式，与原型图一致）。本期该按钮作为入口占位：可见、可点击、点击不报错；具体的自定义编辑功能由后续功能定义。

**Why this priority**: 原型图明确包含该元素，视觉完整性必需；但编辑功能超出本期范围，故为占位实现。

**Independent Test**: 打开弹窗可见底部按钮，点击后无报错且弹窗状态正常。

**Acceptance Scenarios**:

1. **Given** 弹窗已打开，**When** 查看底部区域，**Then** 固定展示"自定义场景/角色"胶囊按钮，样式与原型图一致，且不随话题列表滚动
2. **Given** 弹窗已打开，**When** 点击"自定义场景/角色"按钮，**Then** 应用不报错，弹窗与对话状态保持正常（本期无进一步行为）

### Edge Cases

- 弹窗打开时用户快速反复点击入口或关闭按钮：弹窗状态不错乱、不出现多层叠加
- 某个分类下没有场景数据：中部展示空态提示，不出现空白崩溃
- 场景卡片数据缺少图标或英文名：卡片降级展示（缺图标显示占位图形，缺英文名只显示中文名），不报错
- 正在进行 HITL 中断时打开弹窗并选择场景：中断应答入口仍可用，选择场景不影响未完成的中断流程
- 所选场景在后端没有对应的角色/场景映射：应用场景时给出可感知的失败提示并保留当前场景，不中断对话
- 长对话（消息流很长）状态下打开弹窗：弹窗层级正确覆盖消息流，关闭后消息流滚动位置不跳变

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主页"选场景"入口 MUST 可交互，点击后唤起"选择场景或角色"底部弹窗（替代现有静态占位展示）
- **FR-002**: 弹窗 MUST 从屏幕底部滑出，顶部标题为"选择场景或角色"，右上角提供关闭按钮；弹窗背后主页内容保持可见
- **FR-003**: 弹窗 MUST 在标题下方提供一行可横向滑动的分类胶囊栏，包含"热门、今日话题、日常交流、旅游出行、职场"分类，默认选中"热门"；每次打开弹窗 MUST 均回到该默认状态，不标记当前生效场景（与原型图一致）
- **FR-004**: 弹窗中部 MUST 以双列卡片网格展示当前分类的场景话题，每张卡片 MUST 含图标、中文话题名与英文名；内容超出可视区域时 MUST 可纵向滚动
- **FR-005**: 点击分类胶囊 MUST 即时切换中部话题卡片为对应分类内容，无需页面刷新
- **FR-006**: 点击场景话题卡片 MUST 关闭弹窗，并将该卡片对应的场景与角色**立即应用于当前对话**（下一条消息即按新场景生效）；后端既有 HITL"切换下一个场景"指令（`_new_context_`）MUST 保留，两者并存互不影响
- **FR-007**: 既有对话能力 MUST 保持原行为不变：创建新对话、回复 HITL 中断、展示后端反应与用户自己的消息
- **FR-008**: 弹窗 MUST 提供关闭途径（关闭按钮），关闭后回到打开前状态且不中断进行中的对话流
- **FR-009**: 弹窗底部 MUST 固定展示"自定义场景/角色"按钮（本期为入口占位，不随列表滚动）
- **FR-010**: UI MUST 对齐原型图：弹窗顶部圆角、绿色系主题色与选中高亮、卡片圆角阴影、主页底部输入框与按钮样式（`frontend/docs/mockups/子功能-语音工具-选场景弹出弹窗.png` 为唯一视觉基准）
- **FR-011**: 场景目录数据 MUST 优先由前端静态维护，每个条目 MUST 携带：所属分类、图标、中文名、英文名、对应后端角色与场景标识（遵循 Constitution 原则 III：读取展示优先，不做大规模数据结构改造）
- **FR-012**: 后端适配（如需）MUST 限于最小范围：接受前端传入的角色/场景并生效于对话上下文、必要的字段透出；MUST NOT 改变 Agent 核心逻辑（graph 结构、节点逻辑、状态定义）（遵循 Constitution 原则 II）
- **FR-013**: 所选场景无法在后端生效时，系统 MUST 向用户给出可感知的失败提示，并保留当前已生效的场景，不中断对话
- **FR-014**: 通过弹窗选择的场景 MUST 跨新对话保留（新建对话沿用最近选择的场景），直到用户再次选择其他场景

### Key Entities *(include if feature involves data)*

- **场景目录条目（Scene Catalog Entry）**: 弹窗中一张话题卡片的数据；属性包括所属分类、图标、中文话题名、英文名、映射的后端角色、映射的后端场景
- **分类（Category）**: 分类胶囊栏的一个选项；属性包括分类名称、展示排序；默认选中"热门"
- **教练上下文（Coach Context）**: 后端对话的场景上下文；属性包括角色（role）、场景（scenario）；场景选择的结果即设定该上下文，影响后续教练回复的内容与角度

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在 3 次点击内（入口 → 分类 → 卡片）完成一次场景切换
- **SC-002**: 场景选择后，用户下一条消息收到的教练回复内容与所选场景一致（人工判读通过率 100%）
- **SC-003**: 既有对话功能回归零破坏：新建对话、HITL 应答、消息展示三项既有能力在验收时全部正常
- **SC-004**: 实现界面与原型图逐项目视比对一致：标题栏、分类栏、卡片网格、底部按钮、圆角与主题色、输入框样式
- **SC-005**: 分类切换与弹窗开合无可感知延迟（点击后即时响应）

## Assumptions

- **场景目录数据源**：v1 由前端静态维护；初始集为原型图可见话题（如 爱好/hobby、求职面试/Job Interview、办理登机/Check in、问路/Asking for directions 等），其余分类内容在实现时按主题合理拟定，用户可随时替换静态数据；后续如需后端接口提供目录，属于增量扩展
- **场景与后端映射**：每张卡片数据自带映射到后端角色/场景的字段；后端现有场景轮换组合可作为初始映射子集，未覆盖的场景允许按 Constitution 原则 II 做最小后端扩展
- **"底部有一个 tab"的解读**：按原型图理解为弹窗底部固定的"自定义场景/角色"胶囊按钮，而非页面级 Tab 导航
- **自定义编辑功能**："自定义场景/角色"按钮本期仅展示占位（可见、可点击、不报错），编辑功能由后续功能定义
- **实现方式**：弹窗为组件级实现（无路由跳转），与 001 主 Tab 架构一致；原型图中的手机系统状态栏（时间、电量等）不属于实现范围
- **原型图中的主页元素**：弹窗背后可见的主页顶栏（Ella 头像、音量/设置图标等）已在 001 功能实现，本期不重复改动其结构，仅按原型图做样式对齐
