# Feature Specification: 纠错气泡原句翻译（文A）

**Feature Branch**: `004-correction-translation`

**Created**: 2026-10-26

**Status**: Draft

**Input**: User description: "纠错气泡「文A」按钮点击后展示原句的中文翻译；翻译能力由后端在纠错 tutor 能力范围内按需提供（后端小改），前端沿用 spec-kit 流程开发"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看原句中文翻译 (Priority: P1)

用户在纠错气泡功能行点击「文A」按钮，气泡展开区展示该条英文原句对应的中文翻译，帮助用户确认「自己想表达的意思」并对照理解纠错结果。

**Why this priority**: 纠错场景中译文是理解纠错结果的语义锚点——用户先知道自己说的话被理解成了什么，再看重音、跟读才有意义；003 已将该区域做成「暂无翻译」占位，本功能补齐真实数据即完成主价值。

**Independent Test**: 发送一句英文触发纠错气泡 → 点击「文A」→ 展开区出现中文译文，可独立验收。

**Acceptance Scenarios**:

1. **Given** 一条带纠错气泡的消息已渲染，**When** 点击功能行「文A」按钮，**Then** 该气泡展开区展示原句对应的中文译文
2. **Given** 译文尚在获取中，**When** 展开区处于加载状态，**Then** 展示加载中表现，且不出现「暂无翻译」等占位文案
3. **Given** 译文已展示，**When** 再次点击「文A」收起，**Then** 翻译区收起，原句行与功能行布局保持不变
4. **Given** 译文已获取过，**When** 收起后再次展开，**Then** 直接显示译文，无再次加载等待

---

### User Story 2 - 翻译失败反馈 (Priority: P2)

翻译请求失败（网络异常、后端不可用等）时，用户得到明确的行内提示，且可以重试，气泡其他功能不受影响。

**Why this priority**: 反馈完备性是与 003 FR-012 同源的品质要求——静默失败会让用户误以为按钮坏了，但没有它主流程（US1）依然可用，故列 P2。

**Independent Test**: 断网状态下点击「文A」→ 出现失败提示 → 恢复网络后再次点击可成功获取译文。

**Acceptance Scenarios**:

1. **Given** 翻译请求失败，**When** 用户等待反馈，**Then** 按钮附近或展开区出现行内失败提示文案（无弹窗、无跳转）
2. **Given** 失败提示已出现，**When** 用户再次点击「文A」，**Then** 重新发起翻译请求（可重试）

---

### User Story 3 - 重复查看零等待 (Priority: P3)

同一条消息的翻译在同一次会话中重复查看时直接呈现，不重复发起网络请求。

**Why this priority**: 译文是确定性内容，重复请求只浪费用户等待；属于体验打磨，非主链路。

**Independent Test**: 点击「文A」看到译文 → 收起 → 再展开 → 译文立即显示且无加载态。

**Acceptance Scenarios**:

1. **Given** 译文已获取并保留，**When** 同会话内再次展开该消息的翻译区，**Then** 译文即时显示（无加载中表现）

### Edge Cases

- 翻译请求进行中用户重复点击「文A」？→ 不重复发起请求，维持同一加载态直至返回
- 原句为空（纠错数据异常）？→ 不发起翻译请求，展示不可用提示
- 极长原句？→ 译文在展开区内正常换行，不撑破气泡布局
- 刷新页面后译文状态丢失？→ 再次点击「文A」重新请求即可（翻译不做跨会话持久化）
- 中英混杂原句（如 "Good study, 对对啊"）？→ 译文以中文完整语义为主，可保留必要英文词
- 翻译与音频播放同时进行？→ 互不影响：翻译为纯文本能力，不占用音频通道，不违反 003 的全局音频互斥规则

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 纠错气泡功能行的「文A」按钮点击时，系统 MUST 在该气泡展开区内展示原句对应的中文翻译
- **FR-002**: 翻译获取期间系统 MUST 展示加载中状态，MUST NOT 以「暂无翻译」等占位文案充当加载表现
- **FR-003**: 翻译请求失败时系统 MUST 给出行内轻提示文案，MUST NOT 弹窗、跳转或阻塞气泡其他功能
- **FR-004**: 翻译 MUST 由后端按需提供（用户点击时才请求），MUST NOT 随纠错消息强制透传；后端改动范围与理由 MUST 在 plan.md 留档
- **FR-005**: 同一消息的译文在会话内 MUST 复用首次获取结果，重复查看不重复发起网络请求
- **FR-006**: 翻译的加载与失败 MUST NOT 影响纠错气泡既有能力（语法纠错、AI 发音、循环跟读、复制、收藏、全局音频互斥）
- **FR-007**: 用户 MUST 能通过再次点击「文A」收起翻译区；收起后再展开 MUST 直接显示已获取的译文
- **FR-008**: 译文展示 MUST 保留原句上下文，译文与原句同屏可对照
- **FR-009**: 译文在气泡内的展示位置 MUST 符合「翻译位置布局」（见 Assumptions 第 6 条文字描述）：位于功能行之下、纠错讲解之上，上下各以分隔线与相邻内容区隔

### Key Entities *(include if feature involves data)*

- **翻译结果（TranslationResult）**: 一条纠错消息原句对应的中文译文；关键属性：所属消息、原句文本、译文文本、获取状态（加载中/成功/失败）；生命周期与会话内消息一致，不跨会话持久化
- **纠错消息上下文（复用 003）**: 翻译依附于既有纠错气泡数据，不新增独立消息类型，不改变纠错气泡既有数据结构

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 正常网络下，点击「文A」到译文呈现不超过 5 秒
- **SC-002**: 翻译失败场景 100% 出现可见反馈，无静默失败
- **SC-003**: 已获取译文的消息重复查看时译文即时呈现（无网络等待感）
- **SC-004**: 翻译功能合入后，003 纠错气泡全部验收场景零回归（语法纠错、AI 发音、循环跟读、评分条入口、音频互斥）

## Assumptions

- 翻译方向固定为英→中（产品面向中国英语学习者）；中英混杂原句以中文完整语义输出
- 翻译由后端既有 AI 能力按需生成，不引入第三方翻译服务、不在前端直调外部翻译接口
- 翻译结果不跨会话持久化，前端会话内保留即可满足「重复查看零等待」
- 后端改动限于纠错 tutor 能力范围内新增按需翻译旁路，遵循 Constitution 原则 II（最小改动、plan 留档），不改动父图路由与既有节点逻辑
- 本功能无独立入库原型图（用户提供的参照截图不入 docs/mockups，属用户明确决定）；气泡整体布局与「文A」按钮位置以已入库的 `frontend/docs/mockups/子功能-对话演示气泡-语法纠错场景.jpg` 为对照基准（Constitution 原则 IV）
- **翻译位置布局（文字描述，验收对照基准）**：气泡自上而下依次为——① 原句行；② 功能行（「文A」｜「‼语法纠错」｜「AI 发音」，以竖线分隔）；③ 虚线分隔线；④ **译文行（本功能新增真实数据，替换 003 的「暂无翻译」占位）**；⑤ 虚线分隔线；⑥ 纠错讲解（编号列表）；⑦ 分隔线；⑧ ✅ 正确句行。译文行位于功能行下方第一个内容区，纯中文文本，随内容自动换行
