## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三 Tab 主框架与主页面入口 (Priority: P1)

用户打开应用即进入主窗口：底部是三个 Tab（自由对话 / 精讲课对话 / 我的），
默认选中第一个 Tab"自由对话"并展示主对话页面；另外两个 Tab 是空占位页面。

**Why this priority**: 这是整个应用的主入口，也是后续所有子功能的载体；
没有这个框架，任何子功能都无法落位。

**Independent Test**: 打开应用观察 Tab 栏与默认页面，依次点击三个 Tab 观察切换结果，
即可完整验证。

**Acceptance Scenarios**:

1. **Given** 应用启动，**When** 用户打开主界面，**Then** 底部显示三个 Tab
   （自由对话 / 精讲课对话 / 我的），第一个 Tab 默认选中并展示主对话页面
2. **Given** 用户在任意 Tab，**When** 点击"精讲课对话"或"我的"，
   **Then** 对应的空占位页面正确显示，无报错、无残留内容
3. **Given** 用户在第二个或第三个 Tab，**When** 点击"自由对话"，
   **Then** 返回主对话页面，原有的对话内容与状态保持不变

---

### User Story 2 - 现有对话能力原样迁移 (Priority: P2)

现有已调通的对话能力完整呈现在第一个 Tab 的主对话页面中：
创建新对话、对 HITL（人工介入）请求进行回复、查看后端的实时反应与自己发出的
对话内容。所有行为与迁移前完全一致，不新增也不删减。

**Why this priority**: 对话能力是产品核心价值；迁移必须先保证"功能不丢"，
再谈界面美化。

**Independent Test**: 在新主对话页面内执行一次完整对话流程
（新建会话 → 发送消息 → 回复 HITL → 观察后端反应），
与迁移前的行为逐项对照。

**Acceptance Scenarios**:

1. **Given** 用户在第一个 Tab 的主对话页面，**When** 触发"新会话"，
   **Then** 创建新对话成功，界面回到新会话初始状态（与迁移前一致）
2. **Given** 对话进行中出现 HITL 请求，**When** 用户进行回复，
   **Then** 后端按迁移前相同的方式继续处理
3. **Given** 对话进行中，**When** 后端产生反应，**Then**
   用户能像迁移前一样看到后端的反应与自己发出的消息内容

---

### User Story 3 - 主页面 UI 按原型图优化 (Priority: P3)

在前两个故事完成后，按原型图对主对话页面做视觉优化：
整体大圆角风格、主题色（绿色系消息气泡、高亮激活色）、
底部语音输入框样式等，使界面与原型图一致。

**Why this priority**: 视觉优化依赖功能迁移完成后的稳定界面；
放在最后可避免"边改功能边改样式"造成的返工。

**Independent Test**: 将完成后的界面与原型图逐区域目视比对
（顶部栏 / 消息区 / 底部控制区 / 输入框 / Tab 栏）。

**Acceptance Scenarios**:

1. **Given** P1/P2 已完成，**When** 按原型图优化 UI，
   **Then** 顶部栏、消息区、底部控制区、输入框、Tab 栏的布局结构与原型图一致
2. **Given** UI 优化完成，**When** 用户查看界面，
   **Then** 圆角、主题色、输入框样式与原型图相符，用户目视验收通过

---

### Edge Cases

- 后端暂不可用时：Tab 仍可正常切换；主对话页面沿用现有兼容代码的既有表现，
  本期不新增特殊处理
- 空占位 Tab 被反复点击：不报错、不产生任何副作用
- 对话进行中切换到其他 Tab 再切回：对话内容与进行中状态保持原样
- 语音输入失败（麦克风权限被拒、录音失败、转写接口报错）：输入框区域给出可见
  轻提示（如"无法访问麦克风"/"转写失败，请重试"），页面不中断，键盘文本输入
  始终可用
- 录音进行中切换 Tab 或点击"新会话"：自动取消录音并丢弃已录内容（不转写、
  不发送），输入框区域给出轻提示（如"已取消录音"），页面不中断

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主窗口 MUST 以"自由对话 / 精讲课对话 / 我的"三个 Tab 作为底部主导航，
  顺序、名称与原型图一致
- **FR-002**: 系统 MUST 默认选中"自由对话"Tab 并展示主对话页面
- **FR-003**: "精讲课对话"与"我的" MUST 呈现空占位页面：页面可到达、无报错、
  不承载任何功能（功能由后续特性交付）；页面内容仅为居中提示文字
  "功能建设中"，无插画、无其他元素
- **FR-004**: 主对话页面 MUST 完整保留现有对话能力，行为与迁移前一致：
  创建新对话、回复 HITL 请求、查看后端实时反应与自己发出的消息
- **FR-005**: 主对话页面整体布局 MUST 遵循原型图
  `frontend/docs/mockups/自由对话主窗口_所有其他子功能布局根据这个来-不要参考子功能的布局.png`，
  包含：顶部栏（左侧会话入口图标、居中 AI 对话对象头像与名称、右侧音频与设置入口）、
  中部消息流区域、底部"新会话 / 选场景"按钮区、语音输入框（"点击说话"）
- **FR-006**: 视觉样式 MUST 按原型图执行：大圆角卡片风格、绿色系消息气泡与
  高亮激活主题色、白色圆角语音输入框样式
- **FR-007**: Tab 切换 MUST 不丢失"自由对话"页面的状态（对话内容、进行中的会话
  保持原样）
- **FR-008**: 原型图中消息气泡内部的具体业务内容（评分卡、语法纠错详情、拓展润色等）
  属于后续子功能；本期 MUST 仅保证现有对话内容正常展示于符合原型图布局的页面中
- **FR-009**: 输入框 MUST 提供真实语音输入能力：用户单击"点击说话"开始录音，
  再次单击结束录音并发送（单击-单击模式，非按住说话）；所说内容转换为对话
  消息发送；同时 MUST 保留文本输入方式（原型图中的键盘图标
  用于切换到文本输入）。语音转写由后端提供：后端新增一个最小转写接口（内部复用
  已有工具函数 xfyun_iat_tool_by_audio_data），前端上传录音音频数据、获取转写
  文本后作为消息内容发送；该后端改动属于 Constitution 原则 2 允许的"经确认的
  最小后端修改"。结束录音后自动转写并直接发送，转写文本作为一条普通用户消息
  展示，不经过输入框确认环节
- **FR-010**: 原型图中本期无对应子功能支撑的交互元素（顶部栏左侧会话入口图标、
  右侧音频与设置图标、底部"选场景"按钮）MUST 按原型图完整展示；本期点击它们
  不产生任何行为（不报错、无响应），交互能力由后续子功能接入
- **FR-011**: 迁移完成后，原独立对话页面 MUST 直接删除；新主框架 MUST 成为
  应用唯一入口

### Key Entities *(include if feature involves data)*

- **Tab 项**: 标识、名称、图标、激活状态；本期仅"自由对话"承载内容
- **对话会话（沿用现有）**: 消息列表、进行中的会话状态、待回复的 HITL 请求；
  本期不改变其结构与行为
- **主对话页面区域**: 顶部栏、消息流、底部控制区（新会话 / 选场景）、语音输入框、
  Tab 栏

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 dev 服务器已启动的前提下，页面刷新（热启动）后 3 秒内看到主窗口，
  且无需任何手动操作即停留在"自由对话"主页面
- **SC-002**: 三个 Tab 全部可点击切换，目标页面正确呈现且无报错；
  切回"自由对话"后对话内容与状态 100% 保持
- **SC-003**: 现有对话能力 100% 保留：新会话创建、HITL 回复、后端反应与消息展示
  均与迁移前行为一致，无功能丢失
- **SC-004**: UI 优化后与原型图逐区目视比对（顶部栏 / 消息区 / 底部控制区 /
  输入框 / Tab 栏），布局结构一致，圆角、主题色、输入框样式符合原型，
  用户验收确认通过
- **SC-005**: 用户点击"点击说话"并说出内容后，所说内容以文字消息形式发送并
  展示在对话中（单次操作即可验证）

## Assumptions

- 后端将新增语音转写接口（内部复用 xfyun_iat_tool_by_audio_data），接口契约在 plan 阶段定义

- 原型图为
  `frontend/docs/mockups/自由对话主窗口_所有其他子功能布局根据这个来-不要参考子功能的布局.png`；
  图中元素上的红色闪电标记为设计标注，不是实际界面元素
- 原型图中气泡内部的具体业务内容（评分卡、纠错详情、润色建议、视频通话状态等）
  由后续子功能交付；本期消息区展示现有兼容代码已能呈现的对话内容
- "Ella" 为 AI 对话对象的示例名称与头像；角色配置与切换能力由后续子功能处理
- 界面目标形态为移动端竖屏布局（以原型图为准）
- 现有兼容代码的功能范围以用户确认为准：创建新对话、回复 HITL、查看后端反应与
  自己的对话内容；本期不对这些行为做任何改动
- 迁移完成后原独立对话页面直接删除（见 FR-011）；新主框架是应用唯一入口
- 后续子功能将基于本期主对话页面叠加扩展（新增消息卡片、弹窗等）；
  本期不引入阻碍此类扩展的布局限制
