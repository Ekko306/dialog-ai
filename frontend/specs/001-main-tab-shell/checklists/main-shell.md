**Purpose**: 在进入 `/speckit-tasks` 前，对 spec.md 的需求质量做作者自查——检验需求是否完整、清晰、一致、可测量，而非检验实现是否正确。
**Created**: 2026-10-21
**Feature**: [spec.md](../spec.md)（分支 `001-main-tab-shell`）

**范围与聚焦**（由作者确认）：仅覆盖前端主框架需求（后端转写契约视为已评审，不在本清单内）；聚焦迁移一致性、UI 原型图一致性可测量性、占位元素与后续扩展性；语音输入作为独立风险域不设强制把关项。
**Review Ownership**: 本清单为评审人（作者本人）所有的需求质量自查工件。仅当确认某项需求质量标准已满足时才标记 `[x]`；`[x]` 不代表实现已完成。

## 一、迁移一致性与状态保持

- [x ] CHK001 - spec 是否明确列出"现有对话能力"的完整功能清单（新建会话 / HITL 回复 / 后端反应 / 消息展示），使 SC-003 的"100% 保留"可逐项核对？[Completeness, Spec FR-004/SC-003]
- [x ] CHK002 - "与迁移前行为一致"是否定义了可执行的对照基准（逐项对照表或迁移前行为记录），而非仅依赖记忆比对？[Measurability, Spec US2 独立测试]
- [ ] CHK003 - FR-007 要求保持的状态范围是否明确（消息列表、进行中会话、待回复 HITL、输入框内容），还是仅有"对话内容与状态"的概括表述？[Clarity, Spec FR-007]
- [ ] CHK004 - FR-011 删除旧独立对话页面的时机与前置条件（迁移验收通过后删除，还是与迁移同批进行）是否明确？[Clarity, Spec FR-011]
- [ ] CHK005 - "新主框架是应用唯一入口"是否有对应的验收要求（如不存在任何残留入口或路由指向旧页面）？[Gap, Spec FR-011]

## 二、UI 原型图一致性可测量性

- [x ] CHK006 - SC-004 的"目视比对"是否给出逐区域的判定标准（区域清单、比对顺序、不一致时的处理规则），使作者自评结论可复现？[Measurability, Spec SC-004]
- [x ] CHK007 - 主题色（绿色系消息气泡、高亮激活色）是否定义了具体色值或取色来源（原型图取色 / 主题变量），而非仅风格描述？[Clarity, Spec FR-006]
- [x ] CHK008 - "大圆角风格"是否量化到具体数值或设计变量（如 --radius），而非仅风格描述？[Clarity, Spec FR-006]
- [ ] CHK009 - 顶部栏各元素（会话入口图标、头像与名称、音频/设置图标）的尺寸、对齐方式与内容来源（"Ella"示例名与头像可否替换）是否明确？[Completeness, Spec FR-005/Assumptions]
- [ ] CHK010 - "点击说话"语音输入与键盘文本输入两种形态的默认形态与切换规则是否在需求中明确？[Clarity, Spec FR-005/FR-009]
- [ ] CHK011 - Tab 栏的视觉要求（图标、选中态样式、文字）是否具体到足以支撑与原型图的比对？[Completeness, Spec FR-001/FR-006]
- [ ] CHK012 - 桌面浏览器 / 非移动竖屏视口下的布局表现是否有要求（原型图为移动端竖屏形态）？[Coverage, Assumptions]

## 三、占位元素与后续扩展性

- [ ] CHK013 - 空占位页（FR-003）的呈现是否定义（完全空白或含占位文案），"空页面"的边界是否清晰？[Clarity, Spec FR-003]
