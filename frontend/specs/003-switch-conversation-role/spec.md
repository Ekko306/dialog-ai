# Feature Specification: 切换对话角色与推荐回复

**Feature Branch**: `003-switch-conversation-role`

**Created**: 2026-10-26

**Status**: Draft

**Input**: User description: "点击主对话界面左上角消息入口按钮进入消息页；消息页以会话列表展示系统全部 AI 角色（头像/名称/最后消息预览/时间戳/未读角标）；点击角色（如英语纠错官 Lisa）进入该角色的独立对话页（角色大头像/名称/预置开场白/与主界面一致的输入区）；每条 AI 消息下方展示带风格标签的推荐回复（简单/商务），点击即作为用户消息发送；各角色会话线程独立、历史保留、可反复切换。原型图：frontend/docs/mockups/子功能-切换对话role.png"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 消息入口与角色会话列表 (Priority: P1)

用户在主对话界面点击左上角的消息入口按钮，进入消息页面；消息页以会话列表形式
展示系统提供的全部 AI 角色，每项包含头像、角色名称、该会话最后一条消息预览与
时间戳，有未读消息的角色显示未读角标。用户可通过左上角返回箭头回到原对话，
原对话内容不丢失。

**Why this priority**: 角色浏览与入口导航是切换功能的基础；没有列表入口，
后续的选择与进入都无从谈起。

**Independent Test**: 打开主对话界面 → 点击消息入口 → 观察角色列表内容与样式 →
点击返回 → 确认原对话保留，即可完整验证。

**Acceptance Scenarios**:

1. **Given** 用户在主对话界面，**When** 点击左上角消息入口按钮，
   **Then** 进入消息页面，角色会话列表完整展示
2. **Given** 消息页已打开，**When** 用户查看列表，
   **Then** 每个列表项显示角色头像、名称、最后一条消息预览与时间戳，
   与原型图 `frontend/docs/mockups/子功能-切换对话role.png` 一致
3. **Given** 某角色存在用户未读的新消息，**When** 用户查看列表，
   **Then** 该角色列表项显示未读角标
4. **Given** 用户在消息页，**When** 点击左上角返回箭头，
   **Then** 回到进入前的对话界面，原对话内容与状态保持不变

---

### User Story 2 - 选择角色进入独立对话与会话隔离 (Priority: P2)

用户在消息页点击任一角色（如"英语纠错官 Lisa"），进入该角色的独立对话界面：
顶部展示角色头像大图与名称，首次进入时展示该角色配置中预置的开场白；
每个角色拥有独立会话线程，历史互不串扰、再次进入时保留；用户可反复通过
消息入口返回列表并切换其他角色。

**Why this priority**: 进入角色对话与多会话隔离是本功能的核心价值
（切换学习伙伴）；依赖 US1 的列表入口，故排其后。

**Independent Test**: 依次进入两个不同角色各发送一条消息 → 返回消息页 →
再分别进入这两个角色 → 核对各自的对话内容与开场白，即可验证隔离与保留。

**Acceptance Scenarios**:

1. **Given** 用户在消息页，**When** 点击"英语纠错官 Lisa"，
   **Then** 进入 Lisa 的独立对话页，顶部展示 Lisa 的头像大图与名称，含返回按钮
2. **Given** 用户首次进入某角色对话页，**When** 页面加载完成，
   **Then** 展示该角色配置中预置的开场白（如 Lisa 的"Hi, 我是Lisa。我会用中文
   对你发出的英语进行纠错及润色，再用英语维持对话，我们开始吧！What's new today?"）
3. **Given** 用户分别在角色 A 与角色 B 发送过消息，**When** 返回消息页再次
   进入角色 A，**Then** 仅看到角色 A 的历史对话，看不到角色 B 的任何内容
4. **Given** 用户在任一角色对话页，**When** 通过消息入口再次打开消息页并
   选择其他角色，**Then** 切换成功且此前每个角色的对话历史均保留
5. **Given** 角色对话页，**When** 用户查看输入区与底部工具栏，
   **Then** 与主对话界面一致

---

### User Story 3 - AI 消息的推荐回复 (Priority: P3)

每条 AI 消息（开场白及对话中的回复）下方展示推荐回复选项，按语域风格标注
（如"简单""商务"各一条）。用户点击某条推荐回复，该内容即作为用户消息发送到
当前对话；对话进行中的推荐回复以后端返回为准，未返回时不展示、不阻塞正常对话。

**Why this priority**: 推荐回复是降低开口门槛的增强体验，叠加在对话能力
之上；核心切换链路（US1/US2）不依赖它即可交付。

**Independent Test**: 进入任一角色 → 观察开场白下方推荐回复展示 → 点击
其中一条 → 确认消息发出并出现在对话流，即可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户进入角色对话页看到开场白，**When** 查看开场白下方，
   **Then** 展示带风格标签（如"简单""商务"）的推荐回复气泡，内容来自
   该角色的配置
2. **Given** 推荐回复已展示，**When** 用户点击其中一条，
   **Then** 该内容作为一条用户消息发送并展示在对话流中，对话正常继续
3. **Given** 对话进行中出现 AI 回复，**When** 后端随回复返回了推荐回复，
   **Then** 在该条 AI 消息下方按风格标签展示；**When** 后端未返回推荐回复，
   **Then** 不展示推荐区，消息收发不受任何影响
4. **Given** 推荐回复已展示，**When** 用户选择不点击而是自行输入，
   **Then** 键盘/语音输入方式照常可用，推荐区不阻挡输入

---

### Edge Cases

- 角色数据缺失或无法正常进入（如配置异常）：界面给出明确反馈
  （如"该角色暂时无法使用"），不让用户停留在无响应状态
- 角色尚无任何历史消息时：会话列表的"最后消息预览"展示该角色开场白摘要
  （或等效占位文案），不留空白
- 未读角标的清除：用户进入该角色对话页后，该角色的未读角标清除
- 对话进行中切换到消息页再返回：当前角色的对话内容与进行中状态保持原样
- 推荐回复点击时网络异常：按消息发送失败的一般表现处理，给出可见轻提示，
  页面不中断
- 反复快速在多个角色间切换：不出现内容串扰、错乱或报错

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主对话界面左上角 MUST 提供消息入口按钮，点击进入消息页面
- **FR-002**: 消息页 MUST 提供返回箭头，点击回到进入前的对话界面，
  且原对话内容不丢失
- **FR-003**: 消息页 MUST 以会话列表形式展示全部 12 个内置 AI 角色
  （TalkAI助教Ella、英语纠错官Lisa、英语零基础外教Alicia、全英纠错官Sally、
  AI外教Mira、传译官Zora、AI外教David、雅思考官Dylan、每日俚语分享官Luke、
  Fiona、Piper带你学短语固定搭配、词根词缀记单词Sarah），列表项包含：
  角色头像、角色名称、最后一条消息预览、时间戳
- **FR-004**: 存在未读消息的角色 MUST 显示未读角标；用户进入该角色对话页后
  角标清除
- **FR-005**: 点击列表中任一角色 MUST 进入该角色的独立对话页，顶部展示
  该角色头像大图、名称与返回按钮
- **FR-006**: 首次进入角色对话页 MUST 展示该角色配置中预置的开场白；
  开场白是配置数据，MUST NOT 依赖现场生成
- **FR-007**: 每个角色 MUST 拥有独立会话线程：对话历史互不串扰，切换后保留，
  再次进入时完整恢复（本地保留即可，MVP 不要求后端持久化）
- **FR-008**: 角色对话页的输入区与底部工具栏 MUST 与主对话界面保持一致
- **FR-009**: 每条 AI 消息下方 MUST 支持展示带语域风格标签（如"简单""商务"）
  的推荐回复；用户点击某条推荐回复时，该内容 MUST 作为一条用户消息发送
- **FR-010**: 推荐回复数据来源：开场白附带的首轮推荐回复 MUST 预置于角色
  配置；对话进行中的推荐回复以后端随 AI 回复返回为准，后端未返回时
  MUST NOT 展示且 MUST NOT 影响消息收发
- **FR-011**: 角色无法正常进入时，系统 MUST 给出明确反馈，避免用户无法
  判断操作是否成功
- **FR-012**: 用户 MUST 能在任意角色对话页再次进入消息页并选择其他角色；
  切换能力不因已选角色而丧失

### Key Entities *(include if feature involves data)*

- **角色配置项**: 角色标识、名称、头像、身份介绍、预置开场白、首轮推荐回复
  （含风格标签）；MVP 阶段为前端内置配置数据
- **角色会话线程**: 消息列表、最后一条消息预览、最近活跃时间戳、未读消息数、
  开场白是否已展示；每个角色一个线程，相互独立
- **推荐回复项**: 风格标签（简单/商务等语域）、回复内容、来源
  （角色配置 / 后端随消息返回）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 dev 服务器已启动的前提下，主对话界面点击消息入口后 2 秒内
  看到完整的角色会话列表（12 个角色全部渲染）
- **SC-002**: 点击任一角色后 2 秒内进入其对话页并看到预置开场白；
  12 个角色全部可进入，无一失败
- **SC-003**: 依次在 3 个不同角色中各产生对话后往返切换，各角色历史内容
  100% 保留且互不串扰
- **SC-004**: 点击一条推荐回复后，该内容以用户消息形式出现在对话流中
  （单次操作即可验证）
- **SC-005**: 界面与原型图逐区目视比对（消息页列表项布局、角色对话页顶部、
  推荐回复气泡样式）一致，用户验收确认通过

## Assumptions

- 原型图为 `frontend/docs/mockups/子功能-切换对话role.png`（图 1 为入口位置、
  图 2 为消息页列表、图 3 为角色对话页与推荐回复样式），需求与验收以原型图为准
- 12 个角色的清单、头像、介绍、开场白与首轮推荐回复为前端内置配置数据，
  MVP 不走后端接口；后续如需后端下发在 plan 阶段定义契约
- 消息列表中 "TalkAI助教Ella" 的会话即主对话 Tab 的当前对话线程；
  从消息页进入 Ella 等价于回到主对话界面
- 会话历史仅本地保留，MVP 不要求后端持久化与多端同步
- 对话进行中的推荐回复依赖后端随 AI 回复返回；后端接口契约在 plan 阶段定义，
  后端未支持前该能力按 FR-010 降级（不展示、不阻塞）
- 界面目标形态为移动端竖屏布局（沿用 001 特性确定的目标形态）
- 推荐回复的生成算法与后端实现不属于本特性范围（前端只消费与展示）
