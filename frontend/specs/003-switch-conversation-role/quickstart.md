# Quickstart: 切换对话角色与推荐回复 — 手动验证指南

**Branch**: `003-switch-conversation-role`
**原型图基准**: `frontend/docs/mockups/子功能-切换对话role.png`（图1 入口+chips、图2 消息列表、图3 角色页）

前端无自动化测试框架，本文件为唯一验收手段。按顺序执行，全部通过即验收完成。

---

## 1. 前置条件

| 项 | 要求 | 检查方式 |
|----|------|---------|
| 后端 | `langgraph dev` 正常（graph: talk_agent） | `http://localhost:2024` 可访问 |
| 前端依赖 | `pnpm install` | `pnpm -C frontend -v` |
| 环境变量 | `NEXT_PUBLIC_LANGGRAPH_ASSISTANT_ID` 与 langgraph.json 键名一致 | frontend/.env* |
| 浏览器 | Chrome / Edge 最新版 | 语音输入需 localhost 或 HTTPS |
| 干净起点（可选） | 清掉历史元数据 | DevTools → Application → Local Storage → 删除 `talkai-role-threads` |

## 2. 启动

```bash
# 终端 1：后端（先起）
cd backend
uv run langgraph dev
# 期望: Server started at http://localhost:2024

# 终端 2：前端
cd frontend
pnpm dev
# 期望: Local: http://localhost:3000
```

## 3. 验收清单（对照 spec 用户故事）

### 故事 1：消息入口与角色会话列表（P1）

| # | 步骤 | 期望（对应验收场景） |
|---|------|---------------------|
| 1.1 | 打开 http://localhost:3000，确认主对话界面正常（001 行为不回归） | 主界面完整可用，左上角为消息入口图标（现为按钮） |
| 1.2 | 点击左上角消息入口 | 2 秒内进入消息页，12 个角色会话列表全部渲染（SC-001）；布局对照原型图 2（头像/名称/预览/时间戳） |
| 1.3 | 观察未进入过的角色行 | 预览显示开场白摘要、时间戳为 "—"、无角标（Edge Case） |
| 1.4 | 回到主对话发一条消息产生回复 → 再次打开消息页 | Ella 行的预览/时间戳更新为刚才的对话 |
| 1.5 | 从主对话发起一轮对话并**在其回复进行中**切到消息页 | Ella 行显示未读角标；点击 Ella 返回主对话后，角标清除，对话内容与进行中状态原样保留（FR-002/FR-004） |
| 1.6 | 消息页点击返回箭头 | 回到主对话，原对话内容与状态不变（FR-002） |
| 1.7 | 反复快速 主对话 ⇄ 消息页 多次 | 无白屏、无 console 错误、无内容错乱（Edge Case） |

### 故事 2：选择角色进入独立对话与会话隔离（P2）

| # | 步骤 | 期望 |
|---|------|------|
| 2.1 | 消息页点击"英语纠错官Lisa" | 2 秒内进入 Lisa 对话页（SC-002）：顶部返回按钮 + 中位角色头像+名称 + 音量/设置图标（对照图 3，无标题栏；2026-10-27 用户反馈补充） |
| 2.2 | 观察首屏 | 大头像 + 预置开场白（Lisa 文案 = spec 原文）+ 下方两条推荐回复（简单/商务）；输入区与主界面一致（FR-006/FR-008） |
| 2.3 | 在 Lisa 页发送一条消息 | 对话正常继续（同一 talk_agent graph 行为：话题/纠错/HITL 循环），开场白随首条消息消失 |
| 2.4 | 返回消息页 → 进入另一个角色（如 Mira）各发一条消息 → 返回再进 Lisa | Lisa 页仅显示 Lisa 的历史，看不到 Mira 内容（隔离，US2-3）；Mira 同理 |
| 2.5 | 重复 2.3–2.4 共 3 个角色后往返切换 | 各角色历史 100% 保留互不串扰（SC-003） |
| 2.6 | 在角色 A 的回复**进行中**切到消息页再回到角色 A | 回复内容不丢失：切回后自动附着线程当前状态，进行中的回复继续呈现（join-rejoin，Edge Case） |
| 2.7 | 角色页停在 HITL 输入框时 → 切走 → 切回 | InterruptPrompt 输入框与已键入流程正常（interrupt 状态由 checkpointer 保持） |
| 2.8 | 点击消息列表中的 TalkAI助教Ella | 直接回到主对话界面（等价主线程，FR-003/Assumption） |
| 2.9 | 刷新页面（F5）→ 消息页 → 进入刚聊过的角色 | 历史仍在（threadId 持久化 + 后端 checkpointer）；主对话为 001 既有行为（新会话） |
| 2.10 | 主对话「选场景」应用一个场景（如雅思口语考官）→ 等回复结束后 → 进 Lisa 页等 AutoContinue 自动续跑出新话题 | 新话题人设为英语纠错官（如"我是Lisa"），不出现所选场景的人设（人设防串台，2026-10-27 修复的回归项） |
| 2.11 | 在 Lisa 页点「新会话」出新话题 | 新话题仍是 Lisa 人设（人设由 Store 直写保证：活中断线程走 `_set_context_` 指令；死线程/END 走新线程重启），不轮换成其他角色/场景 |

### 故事 3：AI 消息的推荐回复（P3）

| # | 步骤 | 期望 |
|---|------|------|
| 3.1 | 进入任一角色看开场白下方 | 两条带风格标签的推荐回复胶囊（"简单: …"/"商务: …"，对照图 3）（US3-1） |
| 3.2 | 点击其中一条 | 该内容**立即作为用户消息**出现在对话流并触发回复（SC-004 / US3-2）；标签文字不进入消息正文 |
| 3.3 | 对话进行中观察 | 本期后端未返回推荐 → AI 回复下方无推荐区，消息收发完全正常（FR-010 降级） |

| 3.5 | （后端实现 `suggestions` 后回归）AI 回复携带推荐 | 最后一条 AI 消息下方出现 chips，点击即发送（契约见 contracts/recommended-replies.md） |

## 5. 常见问题

| 症状 | 原因 | 处理 |
|------|------|------|
| 进入角色页历史为空 | 后端重启过（in-memory checkpointer 清空），threadId 失效 | 预期行为（research R8 自愈）；重新对话即可，或清 `talkai-role-threads` |
| 对话无响应 | 后端未起 / assistantId 不匹配 | 核对 .env 与 langgraph.json 键名 |
| 点推荐回复无反应 | 线程运行中或 interrupt 挂起（设计隐藏/禁用） | 等回复完成或先完成 HITL 回复 |
| 消息页角标异常累积 | localStorage 元数据与实际线程状态错位（如手动清了后端） | 清 `talkai-role-threads` 后重试 |
| 隐私模式下列表记忆丢失 | localStorage 不可用（research R8 已知限制） | 正常窗口验证 |
